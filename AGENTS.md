# AI Telegram Bot - Project Knowledge Base

**Updated:** 2026-09-28 | **Commit inspected:** 812b452 | **Branch:** main

## Overview

Node 24/npm TypeScript Telegram bot. Telegraf routes messages, a LangChain agent answers them, Redis stores conversation/news state, and BullMQ polls feeds and delivers subscribed news. LLM roles use OpenAI-compatible providers; Venice is only the suggested default in `config.defaults.json`.

## Structure

```text
src/index.ts           composition root and shutdown hooks
src/lib/config/        config loading and validation
src/lib/llm/           chat, summarizer, and news-relevance model creation
src/lib/telegram/      ingress, commands, chat scope, outbound formatting
src/lib/agent/         live agent invocation, tools, multimodal content
src/lib/memory/        context windows and summary hierarchy
src/lib/redis/         Redis client and raw conversation store
src/lib/news/          feed, article, subscription, query, delivery, scheduler
test/                  Vitest fixtures and behavioral tests
build/                 generated by the build; never edit directly
```

## Setup and commands

Copy `env.sample` to `.env` and set `TELEGRAM_BOT_TOKEN`, `REDIS_URL`, and the configured LLM API-key environment variable (default `LLM_API_KEY`). Redis is required; `docker compose up redis` starts the local instance. `config.defaults.json` is required; copy `config.sample.json` to optional `config.json` for overrides. Objects merge by key and arrays replace wholesale, but a nonempty override is validated as a complete config before merging, so arbitrary partial overrides can fail.

```bash
npm run start:dev
npm run tscheck
npm test
npm run lint
npm run format:check
npm run build
```

## Conventions and project contracts

- TypeScript ESM imports use `.js` specifiers; `@lib/*` resolves through TypeScript and Vitest aliases.
- `src/index.ts` composes shared services. Tests inject Redis, Telegraf, and BullMQ doubles through constructors.
- Memory keys use normalized `private:<id>` or `group:<id>` scope; news subscriptions and Telegram sends use raw chat IDs.
- Private text invokes the agent. Group messages enter shared memory, while ordinary replies require an explicit bot mention. Telegram privacy mode controls which updates Telegram sends; there is no app-level toggle.
- The three configured roles are `chat`, `summarizer`, and `newsRelevance`. Provider settings are shared; role models and vision/web-search flags differ.
- Bootstrap passes the chat role's `systemPrompt` to the agent. Summarizer and relevance prompts are currently constructed in their modules rather than from their role `systemPrompt` fields.
- News polling and delivery are separate jobs. A chat receives scheduled articles only while its subscription is enabled.
- Only one live long-polling instance may use a Telegram bot token; a second produces Telegram 409 Conflict.

## Avoid

- Do not edit `build/` or describe this runtime as Venice-only.
- Do not turn group message persistence into group auto-replies without changing the mention rule deliberately.
- Do not assume every news path is topic-aware: Telegram `/news` and `/summary` use per-chat topics, while the built-in `get_recent_news` tool currently uses the global query path.
