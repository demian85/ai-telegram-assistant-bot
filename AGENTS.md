# AI Telegram Bot - Project Knowledge Base

**Updated:** 2026-10-07 | **Base commit inspected:** ed45c31 | **Branch:** main

## Overview

Node 24/npm TypeScript Telegram bot. Telegraf routes messages, a LangChain agent answers them, Redis stores conversation/news state, and BullMQ polls feeds and delivers subscribed news. Generative roles use OpenAI-compatible chat APIs; news relevance requires the configured provider's typed `/decisions` API.

## Setup and commands

Copy `env.sample` to `.env` and set `TELEGRAM_BOT_TOKEN`, `REDIS_URL`, and the configured LLM API-key environment variable (default `LLM_API_KEY`). Redis is required; `docker compose up redis` starts the local instance. `config.defaults.json` is required; copy `config.sample.json` to optional `config.json` for overrides. Objects merge by key and arrays replace wholesale, but a nonempty override is validated as a complete config before merging, so arbitrary partial overrides can fail.

```bash
npm run start:dev
npm run tscheck
npm test
npm run lint
npm run format:check
npm run build
```

## Conventions and project contracts

- TypeScript ESM imports use `.js` specifiers; `@lib/*` resolves through TypeScript and Vitest aliases.
- `src/index.ts` composes shared services. Pass the same `ChatNewsFilter` instance to query and scheduler paths so decisions, retries, and concurrent evaluations agree.
- Memory keys use normalized `private:<id>` or `group:<id>` scope; news subscriptions and Telegram sends use raw chat IDs.
- Configured generative roles are `chat`, `summarizer`, and `newsPreferences`. The three generative roles use `ChatOpenAI`; relevance uses `VeniceDecisionModel` with `news.decisionModel` and the same provider URL/key. Venice and `jev-latest` are defaults, not a restriction on providers implementing that decision contract.
- Decision questions use built-in eligibility instructions and coverage criteria; there is no configurable relevance system prompt. The removed `llm.roles.newsRelevance` entry, `llm.defaultModel`, and `news.topics` are rejected. Defaults and nonempty overrides require all three generative roles, including an explicit `newsPreferences`; use `news.defaultFilter` for default preferences.
- Bootstrap uses the chat and preference role system prompts. The summarizer still constructs its prompt internally.
- Scheduled news, `/news`, `/summary`, and the feed tool share saved per-chat preferences. Relevance evaluates title and description together using original preferences once, one eligibility Choice and one coverage Score. Compiled criteria remain inspectable; exclusions override scores. Provider-native web search is outside this filter.

## Avoid

- Do not edit `build/` or describe this runtime as Venice-only.
- Preserve the group mention rule when changing ingress: storing a group message must not automatically trigger an answer.
- Never accept chat identity from model tool arguments; `AgentService` supplies the feed tool's trusted invocation context.

## Operational notes

- Only one live long-polling instance may use a Telegram bot token; a second produces Telegram 409 Conflict.
- `npm run news:evaluate` is opt-in and makes one preference-generation call plus nine article decisions without Telegram or Redis writes. Comparison scripts also make live provider calls; see the evaluation docs before running them.
- Local checks live in `package.json`; this checkout has no GitHub Actions workflows. Offline test doubles do not establish live transport/provider behavior.
